# NPC · 거래 · 몬스터 전리품 · 인벤토리 적용 기록

> 2026-10-29 책임 분리 적용: NPC 관계/의뢰/동료 상태는 PlayerEconomy에서 NpcState로, UI는 GameUi로 이동했다. 아래는 기능 도입 당시 기록이며 현재 구조·파일명은 CODE_STRUCTURE.md / REFACTOR_REPORT_2026-10-29.md를 우선 참조한다. 게임 규칙은 유지한다.

적용일: 2026-10-25. OpenGL / C++14 프로젝트. 빌드·게임 실행·렌더링 결과 확인은 사용자 담당이며 이번 작업에서는 실행하지 않았다.

## 적용 범위와 결정

- `npc.md`의 섬별 퀘스트 NPC 3명, 의뢰 완료 후 선택 영입, 호감도 거래를 구현했다.
- 사용자 답변에 따라 사냥꾼·수집가·상인 의뢰와 호감도 범위를 프로토타입으로 적용했다. 8m 돛단배 정원은 기존 1명에서 **동료 2명**으로 변경했다. 상위 선박은 계속 보류한다.
- 이번 요청은 이전의 몬스터 아이템 드랍 중지 지시를 대체한다. 육상 몬스터 40종의 전리품과 장비·강화석, 크라켄 촉수를 지급한다. 미정 드랍은 모두 항목별 50%다.
- 특산품·신규 아이템 가격과 거래 배율은 임시 밸런스 값이다. 한국어 명칭·설명·대화로 표시한다.

## 조작

| 기능 | 조작 |
|---|---|
| 인벤토리 | I 열기/닫기, Esc 닫기 |
| 소지품 선택 | WASD 또는 칸 클릭 |
| 16칸 페이지 이동 | [ / ] |
| 장비 착용 | 선택 후 E / Enter / 하단 착용 버튼 클릭 |
| 장비 해제 | 오른쪽 해당 장비 슬롯 클릭 |
| 동료 해제 | 인벤토리 오른쪽 동료 이름 버튼 클릭 |
| 선박 적재창 | K (이전 I에서 변경), W/S 선택, D 싣기, A 내리기 |
| NPC 대화 | 마을 NPC 가까이에서 E |
| 의뢰/영입 | 대화 중 Q 수락, C 완료, R 영입, D 해제, E/Esc 종료 |
| 상점 | 시설 앞 E, Tab 구매/판매, W/S 선택, Enter 1개 거래 |
| 과도한 판매가 요구 | 판매 화면 P: 매입가 두 배 요구 거절, 호감도 -5 |
| 섬 확인 | T 테스트 맵 왕복, Y 상세/전체, F1~F8 각 섬 항구 이동 |

인벤토리는 첨부 시안처럼 왼쪽 4×4 칸과 오른쪽 머리/무기/상의/하의 장비 십자 배치를 사용한다. 아이콘·한국어 이름·수량·선택 상세를 표시한다. 빈 가방도 16칸을 표시한다. 16칸은 표시 페이지이며 가방을 16종으로 제한하지 않는다. 적재품은 별도 K 창에서 다룬다. 장비 칸의 물건은 소지품 판매 목록에 포함되지 않는다.

인벤토리 표시 최소 크기는 760×540이다. 작은 창은 크기 안내와 닫기 조작을 표시한다. 창이 열린 동안 이동·공격을 차단하지만 세계 시간/해상 사건은 계속 진행된다. 세계 이름표보다 창이 위에 오도록 HUD를 월드 오버레이 뒤에 그린다.

## NPC · 의뢰 · 관계

섬 좌표와 역할(사냥꾼/수집가/상인)을 NPC의 안정적인 식별자로 사용한다. 지형이 로딩되면 마을 내 보행 가능한 지점에 3명을 나누어 배치하며 상점·조선소 이용 지점과 거리를 확보한다. 이름은 섬 식별자로 결정된다.

| 역할 | 목표 | 완료 처리 |
|---|---|---|
| 사냥꾼 | 수락 이후 해당 섬 일반 몬스터 3마리 처치 | 에픽은 집계 제외 |
| 수집가 | 해당 섬 유형 몬스터 전리품 합계 3개 | 가방에서 3개 전달·차감; 다른 섬 유형 전리품/장비 제외 |
| 상인 | 수락 이후 해당 마을 상점 특산품 3개 구매 | 성공한 구매 단위 수 집계 |

의뢰는 NPC마다 한 번 완료한다. 완료 시 호감도 +10, 신뢰 +5, 존경 +3, 영입 제안이 열린다. 금전 보상은 별도로 추가하지 않았다. 정원 초과·선박 미소유·의뢰 미완료 때 영입을 거절한다. 해제해도 완료 상태는 유지해 원래 마을에서 재영입할 수 있다.

호감도는 -100~100이며 정상 거래 성공마다 상인 +1, 과도한 가격 요구 시 -5다. 최근 사건 4개를 NPC 기억으로 보관한다. 신뢰·존경·두려움·원한 상태 필드를 두었지만 적대 전환·동료 전투·자율 일정은 구체 규칙 미정으로 이번에 구현하지 않았다. 동료는 육지에서 보행 경로로 따라오며 승선 시 내 배 갑판에 배치된다. 다른 섬으로 이동하거나 20m 이상 뒤처지면 재합류한다.

퀘스트·관계·장비·소지품·동료는 실행 중 유지되며 청크 재로딩으로 초기화되지 않는다. 일반 월드와 테스트 맵은 기존 여행 스냅샷에 따라 각각 분리된다. 디스크 영구 저장은 이번 범위에 포함하지 않는다.

## 거래 가격

아래는 **기준가**다. 원산지 구매가 = ceil(기준가 × 0.75 × (1 - 호감도 × 0.002)), 원산지 판매가 = floor(기준가 × 0.5 × (1 + 호감도 × 0.002)). 다른 섬 유형에 특산품을 판매하면 1.1배를 적용한다. 실제 양수 가격의 최솟값은 1골드다. 상점 구매 목록은 현지 특산품 4종이며 판매는 소지한 모든 유가 품목을 대상으로 한다.

| 섬 | 특산품 기준가 (골드) |
|---|---|
| 원형 | 곡물 5, 열대과일 8, 목재 10, 약초 7 |
| 초승달 | 진주 35, 조개 8, 소금 4, 건어물 10 |
| U자 | 선박용 밧줄 12, 돛천 16, 목공품 18, 가공 해산물 14 |
| 아령 | 향신료 22, 염료 18, 직물 20, 수공예품 28 |
| 불규칙 | 철광석 18, 구리광석 16, 보석 원석 40, 석재 9 |
| 물방울 | 꽃 8, 향유 30, 꿀 12, 약용식물 15 |
| 분열 | 해조류 6, 게 10, 새우 12, 산호 장식품 24 |
| 암초군 | 성게 14, 해면 16, 희귀 조개 38, 바닷새 깃털 12 |

일반 산호 5, 보스 산호 20, 물고기 2의 기존 기준가를 유지한다. 크라켄 촉수 기준가는 40이다. 비무역 품목 판매에는 기준가와 호감도 배율을 적용한다. 구매·판매는 한 개씩 원자적으로 처리하며 골드 부족·아이템 부족·64비트 보유 한도 초과 시 상태를 유지한다. 기존 일괄 판매 경로를 제거해 선택하지 않은 장비가 판매되지 않도록 했다.

## 드랍 · 장비

육상 처치마다 아래 세 항목을 **각각 독립적으로 50% 판정**한다. 한 마리가 0~3개를 드랍할 수 있다. 한 항목당 수량 1개다.

1. 몬스터 종별 재료 전리품.
2. 해당 종에 배정한 무기·모자·상의·하의 중 하나. 일반은 선원 장비, 에픽은 강철/가죽 장비.
3. 무기 강화석.

| 섬 | 일반 4종 재료 / 에픽 재료 |
|---|---|
| 원형 | 멧돼지 가죽, 늑대 송곳니, 정령 나뭇가지, 거대 벌침 / 고대 나무 심장 |
| 초승달 | 소라게 껍데기, 해안 게 집게, 해파리 결정, 세이렌 비늘 / 수호자의 진주 |
| U자 | 골렘 목재, 뒤엉킨 밧줄, 고블린 주머니, 갑판 쥐 꼬리 / 망령의 파편 |
| 아령 | 카멜레온 가죽, 독거미 실, 생명 덩굴, 원숭이 털 / 환영 비늘 |
| 불규칙 | 골렘 돌조각, 수정 박쥐 날개, 광석 벌레 껍질, 트롤 가죽 / 수정 핵 |
| 물방울 | 맨드레이크 뿌리, 정령 꽃잎, 나비 날개, 독버섯 포자 / 수호 꽃술 |
| 분열 | 늪 도마뱀 비늘, 슬라임 방울, 개구리 가죽, 수초 줄기 / 심연의 핵 |
| 암초군 | 성게 가시, 암초 게 껍질, 바다뱀 비늘, 하피 깃털 / 포식자 이빨 |

일반 재료 기준가 8/적재 중첩 30, 에픽 재료 35/5, 강화석 10/50이다. 특산품·물고기·촉수·산호 중첩은 20, 장비는 1이다. 같은 품목은 기존처럼 선박 한 칸만 사용한다. 가방 표시는 품목별 합산 수량이다.

| 장비 | 기준가 | 공격 | 방어 | 최대 체력 |
|---|---:|---:|---:|---:|
| 선원 커틀러스 | 25 | 4 | 0 | 0 |
| 강철 커틀러스 | 80 | 10 | 0 | 0 |
| 선원 모자 | 12 | 0 | 1 | 5 |
| 가죽 모자 | 35 | 0 | 3 | 12 |
| 선원 상의 | 18 | 0 | 2 | 8 |
| 가죽 갑옷 | 50 | 0 | 5 | 20 |
| 선원 하의 | 15 | 0 | 1 | 6 |
| 가죽 하의 | 40 | 0 | 3 | 15 |

시작 시 훈련용 검을 착용한다(공격 추가 0, 판매 불가). 장비 교체 시 이전 장비를 가방으로 돌려준다. 장비 방어는 플레이어 피격 데미지에서 차감하되 최소 1이다. 선박 체력에는 적용하지 않는다. 체력 장비 해제 시 현재 체력은 줄어든 최대치로 제한한다. F 강화는 새 강화석 아이템을 소비하며 기존 공통 강화 단계를 유지한다.

바닥 아이템은 3.8m 이내에서 지형 경로를 따라 자석 이동·자동 습득한다. 활성 상태로 120초 뒤 정리하고 청크가 해제되면 함께 제거한다. 섬당 바닥 아이템 128개를 넘으면 해당 드랍은 즉시 가방에 지급한다. 크라켄 처치 촉수는 50%로 1개 직접 지급한다. 기존 해적 상자 골드 10~20/촉수 0~1, 낚시 규칙은 유지한다.

## AI 대화 연결부와 한계

`NpcDialogue`는 기본 한국어 대사를 즉시 제공한다. `NpcSystem::SetDialogueProvider`에 선택한 서비스의 함수를 연결하면 이름·역할·의뢰·진행·호감도·신뢰·최근 기억을 값으로 복사해 비동기 요청한다. 현재 실제 모델/API/인증은 연결하지 않았다. 외부 서비스 선정 후 네트워크 타임아웃과 한국어 출력 검증을 제공자에 구현해야 한다.

게임 규칙 변경 함수를 대화 제공자에 노출하지 않는다. 출력은 대사 문자열만 받는다. 요청은 대화 열기/상태 변화 때만 실행하며 동시 대기 2개, 프레임 폴링은 비차단, 종료/다른 대화로 바뀐 응답은 폐기한다. 예외·빈 결과·과도한 결과는 기본 대사를 유지한다. 대기 작업이 있는 종료 시에는 제공자의 작업 종료를 기다릴 수 있으므로 실제 제공자는 반드시 시간 제한을 가져야 한다.

## 구조 · 성능 · 확인

- `ItemCatalog`: 가격·이름·중첩·장비 능력치·드랍 표. 총 86종(기존4 + 특산품32 + 재료40 + 장비8 + 강화석1 + 훈련용 검1).
- `InventoryEquipment` / `NpcRelations`: 경제 상태 변경. `TradeRules`: 호감도·지역 가격.
- `NpcSystem`: NPC Actor/SceneGraph 수명·표시·동료 추적. `NpcDialogue`: 비동기 대사.
- `MonsterItemDrop`: 공유 메시를 사용하는 바닥 아이템 Actor. `PrototypeInventory/Npc/Trade`: 각 입력·화면을 분리했다. HUD도 CallbackActor로 유지하며 별도 UI SceneGraph를 월드 오버레이 다음에 그려 창이 이름표에 가려지지 않게 한다.
- NPC 3종, 드랍 외형 3종은 파일 캐시와 공유 CachedMesh를 사용한다. 인벤토리 아이콘 9종·모서리 4종은 한 번 생성해 기존 UI 배치로 전송한다. 칸별 glDraw 호출을 추가하지 않는다.
- 동료 경로장은 현재 섬에서만 공유하고 셀 이동 시 최대 0.25초 간격으로 갱신한다. 동료가 없거나 승선 중이면 경로장을 만들지 않는다. 청크가 해제되면 NPC/드랍 Actor와 레이아웃 참조를 정리한다.
- `monster_drop_roll`, `item_collected`, `equipment_changed/removed`, `market_buy/sell`, `npc_relation`, `npc_village_created`를 기존 이벤트 로그로 남긴다. 기존 프레임 Draw Call/FPS/업로드 지표와 함께 비교한다. 성능 향상 수치는 미측정이다.

사용자 실행 확인 순서: T→Y 상세 보기→F1~F8에서 NPC 3명 확인→Q 의뢰 수락→처치/자동 습득→I에서 아이콘·수량·착용/해제 확인→수집가 C 완료→R 두 명 영입/세 번째 정원 거절→상점 Tab/Enter 거래→K 적재/하역→T 왕복 후 각 진행 상태 보존 확인. 빈 가방, 17종 이상 페이지, 골드 부족, 재료 부족, 중복 완료, 장착품 판매 제외, 체력 장비 해제도 확인한다.

정적 점검 결과: 전리품 이름 40개/중복 0개, 특산품 기준가 32개/최솟값 4골드, 프로젝트·필터 XML 파싱 성공, 소스/헤더 등록 누락·파일 경로 누락·프로젝트/필터 중복 항목 0개. 일반 월드와 테스트 맵의 MonsterSystem 생성부 모두 퀘스트 집계·습득 콜백을 연결했다. 수정한 C++ 파일의 clang-format `--dry-run --Werror` 검사를 통과했다. 컴파일 성공이나 실제 조작/화면 검증을 의미하지는 않는다.
