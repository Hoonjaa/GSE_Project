# 해적 승선 전투와 40초 약탈

작성일: 2026-10-25. 이전의 해적선 접촉 피해·선체 체력 소진 방식 대신 아래 규칙을 적용한다.

## 확정된 동작

1. 해적선이 접근하거나 접현해도 선박·플레이어에 접촉 피해를 주지 않는다.
2. 해적선 1척마다 빨간 두건과 칼을 든 해적 2명이 있다. 두 척이 모두 접현하면 최대 4명이 승선한다.
3. 해적은 상대 갑판에서 플레이어 갑판으로 시간에 따라 넘어와 추격·근접 공격한다. 해적 체력은 각각 30, 공격은 10/2초다. 기존 플레이어 레벨·최대 체력·장비 공격력·피격 무적 시간을 사용한다.
4. 각 해적선의 해적 2명을 모두 쓰러뜨리면 해당 선박 위에 40초 카운트다운이 시작되고 승선/약탈이 해제된다. 다른 해적선은 별도로 전투·타이머를 관리한다.
5. 내 배의 상대 배 쪽 가장자리에서 E로 해적선에 건너간다. WASD로 이동하고 상자 앞 E로 회수한다. 보상은 해적선당 골드 10~20, 크라켄 촉수 0~1개를 각각 균등 무작위로 정하며 한 번만 회수한다.
6. 해적선의 내 배 쪽 가장자리에서 E로 복귀한다. 40초 안에 복귀하지 못하거나, 해적에게 플레이어 체력이 0이 되면 사망한다. 기존 즉시 항구 회복 흐름을 사용한다.
7. 사망 시 선박 적재품에서 개별 물건 3개를 무작위로 잃는다. 적게 보유했다면 있는 수량만 잃으며 같은 종류가 중복 추첨될 수 있다. 가방·장비·경험치·골드·선박 소유권은 기존 복구 규칙에 따라 보존한다.

보상과 해적 능력치는 사용자 확인을 받은 프로토타입 값이다. 약탈품은 기존 획득물처럼 가방/보유 골드에 지급한다. 크라켄 촉수는 선박 적재 시 중첩 20개이며 판매가는 여전히 미정이다.

## 상호작용과 경계 처리

- 승선 전에는 해적선에 올라갈 수 없으며, 선체를 클릭 공격해서 처치하는 동작을 제거했다. 플레이어 배 위로 넘어온 해적이 전투 대상이다.
- 해적선 승선 지점은 걷기 가능한 갑판 위에서 선택한다. 선체 밖 이동과 돛대·선실 통과를 막는다. 같은 E를 상자 회수와 복귀에 사용하며, 상자 가까이에서는 회수를 먼저 처리한다.
- 카운트다운은 마지막 해적 처치 직후부터 진행하며 약탈 메뉴나 낚시처럼 대기할 수 있는 상황에서도 계속된다. 약탈 후에도 시간은 초기화하지 않는다.
- 해적선에 올라가지 않고 내 배에서 기다린 경우에는 시간 만료로 사망하지 않는다. 시간 안에 복귀한 경우에도 안전하다. 다시 해적선에 올라가면 다시 복귀해야 한다.
- 시간이 끝난 배는 제거 표시되어 렌더링·승선·약탈 대상에서 제외된다. 플레이어가 남아 있으면 먼저 사망/항구 복구를 처리해 숨겨진 선박에 플레이어가 남지 않게 한다.
- 접현한 해적선은 접현 시점의 세계 위치·방향에 정박한다. 플레이어가 항해·회전해도 따라오지 않는다. 이동/회전 시 고정된 해적선과 실제 선체 다각형의 겹침을 검사하고, 약탈 승선·복귀는 두 배가 실제로 가까이 있을 때만 가능하다. 이미 승선한 해적은 플레이어 갑판을 따라 이동한다.
- 타륜 조종 중에도 해적이 플레이어를 공격하므로 E로 조종을 풀고 싸워야 한다. 전투/약탈이 시작된 뒤에는 기존 150m 추격 해제만으로 해적을 없앨 수 없다.
- 해적선 위에서는 내 배의 적재창·낚시·조종을 이용하지 않는다. O/P/F6~F8 강제 소환은 내 배에 돌아온 뒤 이용한다. 기존 R은 개발용 항구 초기화 단축키로 남겨둔다.

## 구조와 성능

- PirateRaid: 배별 승선·해적 전투·보상·타이머·복귀 상태. MarineSystem의 접촉 피해 로직을 대체한다.
- BoardingPirateActor: 해적 모델/칼/체력 표시. PirateDeck과 ShipDeck은 각 갑판의 이동 및 승하선 위치를 제공한다.
- PrototypePirate: 플레이어가 속한 SceneGraph 부모를 선박 사이에서 바꾸고, 갑판 좌표와 세계 좌표를 동기화한다.
- 해적 4명과 보물상자 2개를 시작 시 고정 Actor 풀로 생성한다. 모델/칼/상자는 파일 MeshCache로 재사용하고 동일 메시를 기존 Renderer 인스턴싱 배치에 모은다.
- 갑판 추격은 작은 공용 격자와 목표 셀별 거리장을 사용한다. 걷기 격자는 한 번 생성하고 플레이어의 목표 셀이 바뀔 때만 거리장을 갱신한다. 해적마다 매 프레임 경로 탐색을 생성하지 않는다.
- 새 메시를 접현·전투·처치·약탈·매 프레임 갱신에서 생성하지 않는다. 활성 청크 렌더 제한, 기존 원거리 해적선 저빈도 갱신과 FPS/draw/업로드 로그를 유지한다.
- 선실의 옆 통로를 확보하기 위해 해적선의 선실 너비와 충돌을 함께 줄였으며 캐시 키를 pirate_ship_v2_boarding으로 변경했다.

## 분석 로그

- pirate_boarding_begin: 출발 선박, 해적 2명, 접촉 피해 0, 정박 상태와 세계 위치·방향.
- pirate_boarded_player_ship: 플레이어 갑판 승선 완료.
- pirate_sword_attack / pirate_player_damage: 공격 시도와 실제 적용 피해/플레이어 체력. 무적 시간으로 막힌 피해도 구분한다.
- pirate_crew_hit: 개별 해적의 남은 체력.
- pirate_loot_countdown_begin: 처치 완료 선박, 40초 시작.
- player_boarded_pirate_ship / player_returned_from_pirate_ship: 승선과 남은 시간 내 복귀.
- pirate_loot_claimed: 실제 지급 골드·촉수, 한 번만 처리.
- pirate_loot_window_closed / pirate_player_dead / cargo_lost: 안전한 만료·사망 이유·적재품 개별 손실.

## 확인 범위와 수동 확인 절차

사용자 요청에 따라 게임 빌드·실행·화면 확인은 수행하지 않았다. 프로젝트 XML·파일 경로·소스/필터 등록·PCH 첫 include·clang-format 및 코드 흐름을 정적으로 점검했다. 별도 수치 계산에서는 내 갑판과 해적 갑판의 보행 가능 0.1m 격자가 각각 하나의 연결 영역임을 확인했다(내 갑판 1397셀, 해적 갑판 1276셀). 이 계산은 게임 실행이나 C++ 컴파일 검증을 대신하지 않는다.

1. 해상에서 해적선 접근 또는 Debug F6으로 시작한다. 접현 후 선박 체력이 줄지 않고, 빨간 두건과 칼을 든 2명씩 갑판으로 넘어오는지 확인한다.
2. E로 타륜을 풀고 마우스 클릭으로 해적을 처치한다. 해적이 돛대/선실을 피해서 접근하고 칼 공격으로 플레이어 체력을 줄이는지 확인한다.
3. 해적 2명 처치 후 해당 배 위 40초 카운트다운, 가장자리 E 승선, 상자 E 보상, 같은 상자의 중복 지급 차단을 확인한다.
4. 시간 안에 내 배로 복귀했을 때 생존하고, 해적선에 남아 시간 초과 시 사망·항구 회복·적재 수량 3개 차감이 한 번만 일어나는지 확인한다.
5. 해적에게 플레이어가 패배한 경우에도 같은 3개 손실인지 확인한다. 적재품 0~2개만 있을 때 음수 수량이 생기지 않아야 한다.
6. 두 해적선의 전투/약탈이 겹칠 때 타이머와 보상이 독립적인지, 복귀 후 재승선과 시간 만료 경계가 올바른지 확인한다.
7. 평온 항해/접현/4명 전투/약탈의 CPU update, Actor 수, draw/instance, static 업로드와 캐시 이벤트를 비교한다. 성능 수치는 아직 측정하지 않았다.
8. 접현 후 플레이어 배를 전진·후진·회전시켜도 해적선의 세계 위치·방향이 고정되는지 확인한다. 해적선 쪽 진입은 선체 충돌로 막히고 반대쪽으로는 떠날 수 있어야 한다. 승선한 해적은 내 갑판에 남고, 배가 멀어지면 E로 해적선에 순간이동할 수 없어야 한다.
