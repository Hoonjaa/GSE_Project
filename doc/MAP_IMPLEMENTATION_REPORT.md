## 이번에 확인한 기준

- 섬 크기는 최대 폭 40~80m, 섬 간 간격은 해안선 사이 최소 300m다.
- 가격·호감도 배율·첫 배 가격은 확정하지 않는다. 거래 데이터 구조를 제공하고 구매·판매는 비활성화한다.
- 시작섬은 원형이며 플레이어는 처음에 배를 소유하지 않는다.

## 월드와 지형

MapCatalog에 원형 37%, 나머지 7종 각 9%의 선택표와 특산품 32종을 등록했다. 시작섬은 무작위 형태 선택에서 제외하고 원형으로 고정한다. 유한한 지역 표본에서 형태 비율이 정확히 37:9:…로 맞는다는 뜻은 아니다.

IslandGeneration은 월드 시드와 해역 좌표로 형태·폭·방향·배치를 재생성한다. 하나의 섬이 여러 청크에 걸치며, 각 청크는 겹치는 부분의 정점만 생성한다. 지형 표현, 충돌, 마을, 해도가 같은 IslandLayout을 참조한다.

현재 형태 표현은 64×64 지형 셀이다. 육지 셀 모서리의 볼록 껍질에서 가장 먼 두 점의 거리를 구해 최대 폭을 정규화한다. 분열형·암초군형의 여러 육지는 하나의 섬 그룹으로 취급한다. 시작섬은 기존 큰 튜토리얼을 유지하는 범위에서 상한인 최대 폭 80m로 표현했다. 셀 해상도와 시작섬의 개별 크기는 프로토타입 구현값이다.

해역 격자 간격은 기존 32m 엔진 청크의 16배인 512m다. 중심 흔들림의 차이를 32m 이하로 제한하고, 지형이 중심 반경 80m의 보수적 범위를 벗어나지 않도록 검사한다. 이웃 중심 간 최솟값은 보수적으로 480m 이상이며, 따라서 해안선 간 거리는 480−80−80=320m 이상이다. 이는 최소 300m 조건을 만족시키는 배치 여유이며, 모든 섬 간격을 정확히 300m로 배치한 것은 아니다.

마을은 주요 육지의 바깥 바다와 연결되는 해안에서 시작해 연결된 육지 셀을 선택한다. 실제 육지 셀 수의 1/5 이하만 마을로 표시한다. 건물과 부두의 표시 및 충돌은 동일한 배치 정보를 사용한다. 마을 내부 셀은 몬스터 생성 후보에서 제외한다. 시작섬 적은 시작 위치에서 도달 가능한 셀만 사용하고, 보스도 마을 밖의 유효한 셀로 배치한다.

회색 돌 지형은 다시 추가하지 않았다. 원형 시작섬의 새 항구 위치에 맞춰 플레이어 시작 위치, 부두, 구매 대기 선박, 항구 주민을 연결했다. 플레이어 몸체의 수평 외접 지름과 이동 충돌 반경은 각각 0.4m, 0.2m다.

## 청크 수명과 성능

- 기존 화면 크기/줌 기반 렌더 반경 계산을 유지한다. 32m는 기존 엔진 파티션이며 최종 게임 디자인 수치로 새로 확정하지 않았다.
- 렌더 범위 바깥 1개 청크 테두리는 미리 로딩하고, 2개 청크 테두리를 벗어나면 제거한다. 이 여유 폭은 변경 가능한 프로토타입 스트리밍 정책이다.
- 생성 대기열은 가까운 청크부터 처리하며 업데이트당 1개를 생성한다. 큰 생성 작업을 여러 프레임에 분산하지만, 개별 섬 생성 자체는 여전히 메인 스레드에서 실행된다. 첫 표시 시 순차 로딩이 보일 수 있다.
- 생성되지 않은 청크로의 이동은 허용하지 않는다.
- 비활성 청크는 렌더링과 Actor 갱신을 중지한다. SceneGraph도 비활성 하위 트리의 갱신 목록 구성을 건너뛴다.
- 시작섬의 적·드랍·피해량 표시는 개별 활성 청크 조건을 적용한다. 원거리 전투 시뮬레이션은 현재 일시 중지 후 재개한다.
- 건물·야자수·부두는 공용 MeshCache 자산과 GPU 인스턴싱을 사용한다. 청크 지형은 한 번 만든 정적 메시를 재사용한다.

목표 FPS, 최종 활성 반경, LOD 기준은 확정하지 않았다. 오브젝트 컬링과 백그라운드 생성은 후속 최적화 대상이다.

## 상태 저장

실행 파일 옆 Saves/world_map_v1_20260908/island_X_Z.state에 실제 육지·부두 방문 기록을 저장한다. 시드·해역 좌표·포맷을 확인하고 재방문/재실행 시 복원한다. 지형은 저장된 정점이 아닌 동일 시드로 재생성한다.

현재 저장하는 변경 상태는 방문 기록이다. 퀘스트·화폐·인벤토리·몬스터 처치·동료·선박 소유권의 세션 간 저장은 이번 맵 작업에 포함하지 않았다. 저장 실패 시 미저장 상태를 메모리에 보존하고 해제/종료 시 재시도한다.

## 특산품과 거래

섬별 4종 특산품과 32종 상품 식별자/한글 명칭을 제공한다. MapCatalog::Offers는 현지 특산품 여부와 비활성 구매·판매 견적을 제공한다. TradePricing은 이후 기본 가격과 NPC 호감도 정책을 연결할 인터페이스다.

HUD는 현재 섬의 형태, 특산품, 마을/탐험 구역과 거래 비활성 상태를 표시한다. 값을 임의로 채우거나 무료 거래로 처리하지 않는다.

**첫 돛단배 구매도 비활성이므로 현재 새 게임에서는 승선할 수 없다.** 부두의 선박은 구매 대기 표시다. 첫 배 가격과 자금 획득/구매 규칙을 정하면 소유권 전환과 승선을 연결해야 한다.

## 진단 자료

기존 FPS/draw/CPU 시간/업로드 로그를 유지하고 events.log에 다음을 추가했다.

- map_generator: 생성기 버전, 크기/간격 기준, 현재 스트리밍 정책
- island_generated: 해역 좌표, 형태, 최대 폭, 마을 면적 비율
- chunk_generated: 청크 좌표, 생성 CPU 시간, 남은 대기 수
- world_window/world_stream: 렌더·프리로드·언로드 반경과 로딩·활성·대기 청크 수
- map_visited_saved/map_visited_loaded: 방문 상태 저장/복원

HUD 하단에서도 로딩·활성·대기 청크 수를 확인할 수 있다. 성능 향상 수치는 실측 전까지 미확인이다.

## 사용자 실행 확인

1. 원형 시작섬, 마을 밖 몬스터 배치, 회색 돌 부재, 새 부두와 시작 위치를 확인한다.
2. 육지·부두·건물 충돌과 청크 경계 이동, 해도와 실제 지형의 일치를 확인한다.
3. 지름 0.4m 플레이어의 장비 위치와 한글 HUD를 확인한다.
4. 거래 비활성 안내, 배 미소유 상태의 승선 제한을 확인한다.
5. 종료 후 다시 실행해 map_visited_loaded를 확인한다.
6. 이동에 따른 청크 생성 대기와 원거리 비활성화 로그를 확인한다. 다른 섬의 실제 항해 검증은 선박 구매 규칙을 활성화한 뒤 수행한다.

검토 범위는 소스 포맷, 프로젝트 등록, 오래된 월드 API 참조, 요구사항·수치의 정적 대조다. 게임 빌드와 실제 재생 결과는 아직 확인하지 않았다.
