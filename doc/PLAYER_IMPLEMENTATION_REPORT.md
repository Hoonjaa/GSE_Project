# player.md 적용 보고서

작성일: 2026-10-24

## 구현 범위

- 기존 OpenGL 렌더러, Actor/SceneGraph, 월드 청크와 지상 레벨을 사용한다.
- 약 0.4m 플레이어, 원형 시작섬, 배 미소유 시작과 산호 전리품 판매 → 50골드 → 8m 돛단배 구매 흐름을 유지한다.
- Land / Deck / Helm 상태를 분리했다. 승선하면 플레이어 Actor가 선박의 자식이 되어 이동·회전·흔들림을 함께 따른다.
- 갑판은 선체 다각형과 0.2m 플레이어 반경으로 제한하고 돛대·선실을 피한다. 타륜 앞에서 조종을 시작하며 갑판 상태에서는 클릭 근접 공격과 낚시가 가능하다.
- 선박 적재창은 가방과 독립된 5종류 슬롯이다. 현재 일반 산호·보스 산호·물고기·크라켄 촉수는 종류별 20개이며 같은 품목을 여러 슬롯으로 나누지 않는다.
- 아이템 ID와 이름·가격·중첩 조회를 일반화했다. 특산품 32종의 ID/기존 섬 데이터는 연결하지만, 가격·중첩 한도·호감도 공식이 미정이므로 거래와 적재는 활성화하지 않는다.

## 조작

| 상황 | 입력 | 동작 |
|---|---|---|
| 육지, 정박 선박 근처 | E | 가까운 갑판 가장자리로 승선 |
| 갑판 | WASD | 카메라 기준 이동, 선체 밖 이동과 돛대·선실 통과 방지 |
| 타륜 근처 | E | 조종 시작, WASD 항해 |
| 타륜 조종 중 | E | 조종 해제, 갑판 활동 |
| 육지 쪽 갑판 가장자리 | E | 가까운 보행 가능한 해안·부두로 하선 |
| 갑판 | 마우스 좌클릭 | 방향과 사거리·돛대/선실 가림을 검사하는 근접 공격 |
| 갑판 가장자리 | F | 낚시 시작/종료, 5초마다 물고기 1마리를 가방에 지급 |
| 선박 위 또는 소유 선박 정박 조선소 | I | 별도 선박 적재창 |
| 적재창 | W/S, D, A | 4개 현행 품목 선택 / 가능한 수량 싣기 / 해당 종류 전부 내리기 |
| 적재창 | I/E/Esc | 닫기 |
| 해상 승선 중, 메뉴 닫힘 | O / P | 토네이도 / 크라켄 즉시 소환, Debug·Release 공통 |
| 일반 화면 | B | 후처리 전체 켜기/끄기 (기존 P에서 이동, 조선소 메뉴의 B 구매는 유지) |
| 상점 | S | 가격이 설정된 가방 아이템 전부 판매, 촉수·특산품 보존 |
| 토네이도 포획 | A/D | 키를 놓았다 다시 누르며 번갈아 12회, 제한 5초 |

기존 지상 F 강화, 달리기/항해 가속 Space, 휠 줌과 R 항구 복귀를 유지한다. 조종 중에는 갑판 공격·낚시를 할 수 없다. 이동·공격·조종·메뉴 진입 시 낚시를 종료한다. 적재 메뉴는 이동 입력을 차단하되 해상 전투 시간은 흐른다.

## 사용자 확정값

| 항목 | 값 |
|---|---|
| 첫 배 | 50골드 / 8m / 동료 정원 1 / 적재 5종 |
| 선박 체력 | 100, 지상 플레이어 체력과 별도 |
| 해적 | 반경 150m 안 최대 2척 / 각 50m 접근 시 추격 / 체력 60 / 2초마다 10 피해 |
| 해적 승리 | 두 척 모두 격파 |
| 크라켄 | 승선 시간 30초마다 1% 판정 / 촉수 4개 / 각 체력 30 / 2초마다 5 피해 |
| 크라켄 승리 | 4개 모두 절단 → 촉수 1개, 중첩 20, 판매 불가 |
| 토네이도 | 승선 시간 20초마다 1% 판정 / 2~3개 / 어두워짐·비·번개·천둥 |
| 포획 탈출 | 5초 안에 A/D 번갈아 12회, 같은 키 반복은 무효 |
| 적재 손실 | 해적 패배 3개 / 크라켄 패배 2개 / 토네이도 실패 4개 |
| 낚시 | 물고기 1종 / 5초당 1마리 / 적재 중첩 20 / 판매 2골드 |

손실은 전체 적재 수량에서 개별 물건을 균등 추첨하고 매번 남은 수량으로 다시 추첨한다. 예를 들어 수량 5·11·2인 18개에서 4개를 잃으면 합계 14개가 남는다. 같은 종류가 중복 선택될 수 있다. 총량이 부족하면 남은 만큼만 잃고 가방은 보존한다.

## 이번 프로토타입의 임시 동작

아래는 최종 밸런스 확정값이 아닌 실행 가능한 기본 동작이다. 향후 기획에 맞춰 교체한다.

- 주요 조우는 한 번에 하나만 활성화한다. 다른 조우 중에도 확률 판정 로그는 남기지만 당첨 조우를 대기열에 쌓지 않는다.
- 최초 해적 배치는 선박에서 120~150m 사이 안전한 바다를 유한 횟수 탐색한다. 지형 때문에 실패하면 두 척보다 적을 수 있다.
- 조우가 없을 때 마지막 배치 중심에서 150m 넘게 이동하면 순찰선을 다시 배치한다. 해적 추격 중 이 범위를 벗어나면 추격을 종료하고 다시 배치한다.
- 해적은 안전한 물길로 직접 추격하며 복잡한 해안 우회 경로 탐색은 아직 없다. 선박 간 겹침을 줄이는 근접 거리 검사를 적용한다.
- 갑판 공격은 기존 레벨·무기·강화 공격력을 사용한다. 쿨다운 0.42초, 기본 사거리 2.7m, 전방 120도이며 표적 반경을 포함한다. 해상 적 처치의 별도 경험치·해적 보상은 미정이다.
- 폭풍은 최대 60초, 토네이도는 약 8m 크기, 포획 반경 8m, 이동 속도 2m/s다. 성공·실패 시 폭풍을 종료한다.
- 선박 파괴 시 손실을 처리하고 기존 항구 복귀/회복 흐름으로 이동한다. 소유권과 남은 적재품은 유지한다.
- 육지로 내려도 근처 선박의 진행 중 조우는 계속된다. 선박이 활성 청크 밖으로 벗어나면 조우 시간을 정지한다. 새 확률 판정은 승선 중에만 진행한다.
- 선박 수리 메뉴, 8m 이후 성장, 실제 동료 AI, 퀘스트, 탐험 고가품, NPC 호감도와 특산품 가격 공식은 후속 작업이다.
- 경제·선박·해상 조우는 세션 메모리 상태다. 프로그램 재시작 저장/복원은 구현하지 않았다. 기존 월드 방문 기록 저장은 별개다.

## 코드와 자원 구조

- ShipDeck: 선체 내부 이동·가장자리·타륜 위치·장애물/공격 가림.
- PrototypePlayer / PrototypePlayerHud: 승하선·조종 상태 전환, 낚시, 적재창과 한국어 안내.
- PlayerEconomy: 일반 아이템 수량, 가격·중첩, 적재 이동, 개별 수량 무작위 손실.
- MarineSystem: 확률 시계·순찰·해상 전투·포획과 보상.
- MarineActors / MarineMeshes: Actor 모델·체력 표시·폭풍·오디오, 파일 캐시 모델.
- Renderer/Shaders: 인스턴스별 비/토네이도 GPU 애니메이션과 장면 광량. HUD 밝기는 유지한다.
- WinMM의 메모리 WAV로 합성 천둥을 재생하며 외부 오디오 다운로드는 없다.

새 선박/촉수/토네이도/비/번개/타륜/낚싯대/공격 궤적 메시를 시작 시 LoadOrCreate로 준비하고 재사용한다. 같은 종류 모델은 기존 instanced batch에 모인다. 승선·조종·확률 당첨·매 프레임 갱신에서 메시를 만들지 않는다. 고정 풀은 해적 2·촉수 4·토네이도 3개다.

활성 청크 밖 모델은 렌더하지 않는다. 원거리 추격 해적은 0.2초 누적 갱신으로 분리하고, 미로딩 바다 판정은 섬 descriptor만 사용하므로 원거리 해적 때문에 청크/메시를 생성하지 않는다. 비와 소용돌이 변형은 GLSL에서 처리한다.

## 로그 및 수동 확인

events.log에 marine_rng_seed, pirate_patrol_repositioned, pirate_aggro, kraken_roll, tornado_roll, marine_event, marine_target_hit, ship_damage, tornado_escape_input, cargo_lost, player_boarded, player_disembarked, player_helm_engaged/released, fishing_toggle/catch, item_collected, cargo_store/unload, inventory_items_sold를 남긴다. 오디오 실패는 storm_thunder_audio_unavailable이다.

기존 FPS/draw call/CPU/메시 업로드/인스턴스 로그를 함께 비교한다. 비 96줄을 개별 draw하지 않고 하나의 정적 메시로 제출하며, 동일 토네이도는 같은 배치에 모인다. 실제 FPS나 draw 감소량은 아직 측정하지 않았다.

사용자 요청에 따라 빌드·실행·렌더링 결과 검증은 수행하지 않았다. 프로젝트 XML·파일 경로·소스/필터 등록 일치·PCH include·이전 심볼 제거·확정 규칙 문서·clang-format 19 검사 등 정적 점검을 수행했다. C++ 컴파일과 GLSL 실행 검증은 포함하지 않았다. 다음은 사용자가 실행 후 확인할 절차다.

1. 전리품 판매 → 50골드 구매 → 부두 승선. 갑판에서 플레이어가 보이고 타륜 앞까지 이동할 수 있는지 확인.
2. 타륜 E 조종/해제, 회전 후 갑판 이동과 해안 하선, 돛대·선실·선체 경계 충돌 확인.
3. 가장자리 F로 5초 간격 물고기 지급, 이동/공격 시 중단, 상점 2골드 판매 확인.
4. I 적재창에서 20개 상한·동일 품목 1슬롯, 내리기·판매 및 촉수 판매 제외 확인.
5. Debug·Release 모두 승선 후 O 토네이도 / P 크라켄을 소환한다. 해적 추격·폭풍·포획 중에도 교체되는지 확인한다. Debug 전용 F6 해적 / F7 크라켄 / F8 폭풍도 같은 교체 경로를 사용한다. B는 후처리 토글이다.
6. 선박 체력·갑판 공격·촉수 4개와 보상, A/D 12회 성공·같은 키 반복 실패·5초 초과 손실을 확인.
7. 물건 18개 적재 후 폭풍 실패 시 합계 14개, 가방 수량 불변을 확인.
8. 폭풍의 암전·비·번개·천둥, HDR on/off, 원거리 청크와 재방문, 전후 draw/CPU/업로드 로그를 비교한다.

## 2026-10-24 출현 점검 및 O/P 수동 소환

- 기존 실행 로그 x64/Debug/Logs/run_20261024_081802_684_18584/events.log에서 크라켄 판정 14회·당첨 0회, 토네이도 판정 22회·당첨 0회를 확인했다. 이 세션에서 판정 시계는 진행됐지만 모두 미당첨이었다. 출현 후의 화면까지 이 로그로 검증한 것은 아니다.
- 자연 발생은 기존 30초/20초마다 1%를 유지한다. 다른 조우 중이면 당첨돼도 출현하지 않는다. 해당 제한이 없더라도 평균 첫 당첨 시간은 크라켄 50분, 토네이도 약 33분 20초다.
- 확률 로그 kraken_roll/tornado_roll에 value(0~99), encounter, result(miss/started/blocked_busy)를 추가해 미당첨과 조우 제한을 구분한다.
- O/P는 확률과 기존 조우 제한을 우회하고 자연 발생과 같은 Begin 생성 경로를 호출한다. 폭풍·포획·촉수·추격 상태를 정리한 후 새 조우로 교체한다. 교체 자체로 보상이나 적재 손실을 처리하지 않고 선박 체력은 유지한다.
- 토네이도 포획 중에도 교체할 수 있다. 대문자도 처리하며, 육지에서는 승선 안내를 표시한다. 메뉴가 열려 있으면 소환하지 않는다.
- 수동 폭풍도 자연 발생처럼 기본 18m 지점에 2~3개를 생성한다. 기존 F8의 첫 토네이도를 4m에 두어 즉시 포획하던 동작을 통일했다. 해안 충돌 시 안전한 선박 위치로 대체하는 기존 규칙은 유지한다.
- 수동 소환 로그는 marine_forced: kind(크라켄 2/토네이도 3), replaced(교체된 조우), health다. 소환 조건 실패는 marine_force_rejected다.
- 입력 → 기존 조우 정리 → 생성 → 갱신 → 활성 청크 렌더링 경로와 기존 로그를 점검했다. 이번 수정의 게임 빌드·실행·렌더링 결과 확인은 수행하지 않았다.
