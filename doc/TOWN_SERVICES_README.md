# 마을 조선소·상점과 첫 돛단배

2026-10-24 사용자 확정 사항을 반영한 구현 기록.

> 최신 NPC 작업으로 동료 정원은 2명, I 인벤토리/K 적재창, 상점은 선택 구매·판매/호감도 거래로 변경됐다. 전리품도 새 종별 드랍을 사용한다. 아래는 초기 구현 기록이며 현재 조작·가격·적용 범위는 [NPC_INVENTORY_IMPLEMENTATION_REPORT.md](NPC_INVENTORY_IMPLEMENTATION_REPORT.md)를 우선 참조한다.

## 가격과 단계

| 항목 | 규칙 |
|---|---|
| 일반 산호 전리품 | 1개 판매 시 5골드 |
| 보스 산호 전리품 | 1개 판매 시 20골드 |
| 첫 선박 | 배 미소유 → 50골드로 8m 돛단배 구매·업그레이드 |
| 동료 정원 | 1명 |
| 선박 적재 | 5종류 슬롯 |
| 현재 두 전리품의 중첩 한도 | 각각 한 슬롯에 최대 20개 |

별도의 5m 배 구매나 추가 강화 비용은 없다. 8m보다 높은 단계는 이번에 만들지 않았다.
동료 정원 데이터는 제공하지만 실제 NPC 영입 시스템은 별도 구현 대상이다.
특산품 32종의 거래 가격과 호감도 배율도 아직 미정이다.

## 마을 시설

- 모든 섬의 마을에 상점과 조선소를 각각 하나씩 배치한다.
- 기존 마을 마스크 안에서 걸어갈 수 있고 시설 모델이 들어갈 두 구역을 예약한다. 마을 면적은 섬 육지의 20% 상한을 유지한다.
- 조선소는 부두 가까이에, 상점은 조선소와 떨어진 위치에 배치한다. 주택은 시설 진입 공간을 피해 생성한다.
- 주황색 구역은 상점, 파란색 구역은 조선소다. 머리 위에 한글 이름이 표시된다.
- 시설은 TownServiceActor로 관리하며 청크 비활성화/해제 규칙을 따른다.
- 모델과 지면 표시는 공유 MeshCache 자산을 사용한다. 매 프레임 시설 Mesh를 다시 만들지 않는다.

## 전리품과 골드

프로토타입의 일반 산호 적/산호 보스를 처치하면 각각 판매용 전리품 1개를 추가로 드랍한다.
기존 무기·강화석 드랍과 성장 시스템은 유지한다. 이 둘은 상점의 일괄 판매 대상이 아니다.
판매용 전리품도 기존 자석 습득 동작을 사용하며 소지품 수량으로 모은다.
드랍 Actor가 기존 상한에 도달했을 때는 판매용 전리품을 즉시 소지품으로 회수해 보상을 잃지 않도록 한다.

상점은 소지품의 일반/보스 산호 전리품을 모두 판매하고 해당 수량을 차감한다.
판매할 수량이 없으면 골드를 지급하지 않는다. 배에 적재한 물품은 조선소에서 먼저 내려야 판매할 수 있다.
초기 골드는 0이며, 일반 전리품 10개 판매의 기대 수익은 50골드다.

## 이용 방법

1. 시설 구역 가까이에서 E를 눌러 메뉴를 연다.
2. 상점: S로 소지 전리품을 모두 판매한다.
3. 조선소: B 또는 U로 50골드 돛단배 구매·업그레이드를 실행한다.
4. 이미 구매한 경우 재구매하거나 추가 골드를 차감하지 않는다.
5. E 또는 Esc로 메뉴를 닫는다. 메뉴가 열려 있을 때 Esc는 게임 종료 대신 메뉴를 닫는다.
6. 구매한 배는 이용 중인 조선소의 부두 밖 정박 위치에 배치된다. 부두 끝에서 E로 승선한다.

시설 메뉴에서는 플레이어 이동과 공격을 중지하고 입력을 메뉴에 전달한다.
골드 부족이나 부두 주변 청크 로딩/정박 공간 문제로 구매할 수 없으면 골드를 차감하지 않는다.
선체 모델의 수평 길이는 8m이며, 정박 간격·선체 충돌·승하선 탐색도 선체 크기에 맞춘다.

## 선박 적재

조선소에서 소유 선박을 해당 부두에 정박한 뒤 이용한다.

| 키 | 동작 |
|---|---|
| 1 | 소지 일반 산호 전리품을 가능한 만큼 적재 |
| 2 | 소지 보스 산호 전리품을 가능한 만큼 적재 |
| 3 | 일반 산호 전리품을 모두 내리기 |
| 4 | 보스 산호 전리품을 모두 내리기 |

같은 아이템은 항상 같은 슬롯을 사용한다. 20개를 채운 뒤 같은 아이템으로 두 번째 슬롯을 만들지 않는다.
소지품에 일반 전리품 25개가 있으면 20개를 적재하고 5개는 소지품에 남는 것이 기대 동작이다.
두 종류를 적재하면 2/5종을 사용한다. 현재 적재 UI의 대상은 두 판매용 전리품이며, 나머지 3종 슬롯은 향후 아이템을 위한 여유다.
중첩 상한은 PlayerEconomy의 아이템별 규칙에서 관리하므로 아이템마다 다른 값으로 확장할 수 있다.

현재 경제·선박 소유권·적재는 실행 중 메모리 상태다. 사망/R 귀환 시 유지하며, 프로그램 재실행을 위한 저장은 아직 추가하지 않았다.

## 구조 및 분석 로그

- PlayerEconomy: 골드·소지 전리품·선박 구매·적재 이동. 수량/골드 검증 후 변경한다.
- GameplayActors/LevelOne: 전리품 드랍과 습득을 경제 객체에 전달한다.
- IslandLayout/World: 마을 시설 위치, 청크 소유, 접근 구역, 정박 위치.
- TownServiceActor: 시설의 공유 모델과 한글 간판.
- PrototypeServices: 메뉴 입력, 현재 조선소와 소유 선박의 위치 검사, 구매 결과 표시.

events.log에 coral_loot_collected, coral_loot_sold, sailboat_purchased, cargo_store, cargo_unload를 남긴다.
기존 프레임/FPS/draw/업로드 로그로 시설 모델과 간판의 비용도 비교할 수 있다.
시설 추가로 배치 종류가 늘지만 같은 시설 모델은 여러 마을에 걸쳐 인스턴싱된다.

## 사용자 확인 항목

아래는 실행 전 기대 동작이며 측정/실행 결과가 아니다.

- 일반 전리품 9개 판매 → 45골드. 구매 실패 후 45골드와 배 미소유 상태 유지.
- 일반 전리품 1개 추가 판매 → 50골드. 구매 후 0골드, 8m 배 소유.
- 구매 완료 후 B/U 반복 → 추가 차감이나 선박 복제 없음.
- 일반/보스 혼합 판매 → 일반 수량×5 + 보스 수량×20만 지급하고 판매 수량 0.
- 적재/내리기 반복 → 소지품과 적재 합계 보존, 종류별 20개 상한, 중복 슬롯 없음.
- 사망/R 귀환 후 골드·전리품·소유 선박·적재 상태 유지.
- 다른 마을에서도 상점/조선소가 각각 하나씩 표시되고 사용 가능한지 확인.
- 8m 선체의 육지/부두 충돌, 승선/하선, 메뉴 닫기와 입력 복귀를 확인.

소스와 프로젝트 등록을 정적으로 점검하며, 빌드·게임 실행·렌더링 확인은 사용자가 수행한다.
