메시 캐시와 셰이더 구성
======================

1. 고정 메시
Geometry 함수로 Mesh를 구성한 뒤 CachedMesh(std::move(mesh))로 보관한다.
CachedMesh는 불변 정점 데이터를 공유한다. 복사한 핸들은 같은 GPU 버퍼를 사용한다.
같은 모양을 여러 곳에 배치할 때는 핸들을 공유하고 Submit의 위치/회전만 바꾼다.
서로 별도로 생성한 데이터의 내용 비교나 자동 중복 제거는 하지 않는다.

첫 Submit에서만 VAO/VBO를 생성하고 GL_STATIC_DRAW로 업로드한다.
이후 프레임은 기존 GPU 버퍼를 재사용하며 월드 셰이더에서 이동/회전/투영한다.
캐시는 Renderer 소유이며, 모든 핸들이 해제되면 다음 Begin에서 GPU 자원을 해제한다.
따라서 월드 청크가 사라질 때 캐시가 무제한 누적되지 않는다.
메시를 변경하려면 새 Mesh를 만든 후 CachedMesh 핸들을 교체한다.

적용 대상: 섬 지형/건물/장식, 레벨 1 지형, 배, 플레이어/NPC, 검/발밑 표시,
일반 몬스터/보스와 피격 변형, 공격 예고 원, 드랍 무기/강화석, 근접 공격 궤적.
파도, 항적, 깃발, 새 등 정점이 프레임마다 변하는 효과와 UI는 기존 스트리밍 경로를 유지한다.
GPU 인스턴싱은 이번 변경에 포함하지 않는다. 공유 메시라도 인스턴스마다 드로우한다.

2. 외부 셰이더 파일
SimpleGame/Shaders/World.vs + World.fs: 캐시된 월드 메시, 등각 투영 및 HDR 색상 변환.
SimpleGame/Shaders/SolidRect.vs + SolidRect.fs: 동적 메시 및 한글/UI 배치.
SimpleGame/Shaders/PostProcess.vs + PostProcess.fs: HDR 톤 매핑, 비넷, 외곽 흐림 합성.
SimpleGame/Shaders/PostProcess.vs + Blur.fs: 블러 패스.

GLSL은 C++ 문자열이 아닌 독립된 .vs/.fs 파일에서 읽는다.
실행 파일 옆 Shaders 폴더를 사용하며 Visual Studio 빌드 후 해당 폴더로 복사한다.
파일 변경 사항은 다음 프로그램 시작 시 반영된다. 런타임 핫 리로드는 지원하지 않는다.

3. 사용자 빌드/실행 확인 항목
기존과 동일한 화면 배치와 한글 HUD, HDR 켜기/끄기, 화면 크기/줌 변경을 확인한다.
이동/회전/승하선, 몬스터 피격 색상, 보스 예고 원, 아이템 부유와 공격 궤적을 확인한다.
멀리 항해한 후 돌아왔을 때 청크가 정상적으로 재생성되는지 확인한다.
이번 작업에서는 빌드 및 게임 실행을 수행하지 않았다.
