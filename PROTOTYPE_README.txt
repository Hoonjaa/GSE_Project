OpenGL 렌더링 프로토타입 01
작성일: 2026-09-08

이번 범위
---------
기획서의 밝은 대항해 시대 분위기를 확인하고, 항구에서 출항해
절차 생성 섬으로 이동하는 기본 조작을 검토하기 위한 첫 구현이다.
화면의 '미지의 항로'는 임시 프로토타입 표기이며 정식 게임명이 아니다.

포함된 구현
-----------
- OpenGL 3.3 Core / GLEW / FreeGLUT 기반 렌더러
- 고정 아이소메트릭 직교 투영, 깊이 버퍼, 면별 색상 명암
- 모래 해안, 초록 지면, 야자수, 항구 건물, 등대, 부두
- 입체 도형으로 구성된 캐릭터, 범선, 시각용 NPC
- 파도 무늬, 선박 상하 움직임과 항적, 깃발 및 갈매기 애니메이션
- 화면 방향 기준 캐릭터/선박 이동, 해안 및 주요 건물 충돌, 승선/하선
- 플레이어를 따라가는 카메라, 줌, 창 크기 변경 대응
- 64비트 청크 좌표 + 청크 내부 double 좌표
- 카메라 주변 상대 좌표로 변환한 렌더링
- 시드 20260908 기반 섬 생성, 주변 청크 캐시 및 먼 청크 해제
- 현재 로딩된 지형을 표시하는 로컬 지도, 상태 및 조작 안내
- 실행 파일 위치 기준 셰이더 로딩과 빌드 후 셰이더 복사 설정
- RGBA16F HDR 장면 버퍼, 톤 매핑, 비넷과 외곽 블러 후처리

현재 단계에서는 텍스처와 외부 모델 없이 색상 메시만 사용한다.
캐릭터 역시 입체 도형이다. 최종 2D/3D 캐릭터 방식 확정은 아니다.
지형은 평탄한 섬과 단순한 장식으로 구성하며, 고급 조명/그림자는 없다.
게임 안내와 상태 표시는 한국어를 기본으로 한다.
Windows 맑은 고딕의 한글을 GDI로 래스터화하고 OpenGL 글꼴 텍스처에 캐시한다.
실행 환경에 한글을 지원하는 맑은 고딕 글꼴이 필요하다.
게임 문자열은 UTF-8이며 모든 빌드 구성에 /utf-8 옵션을 적용했다.
이후 NPC 대화도 한국어를 기본으로 작성·생성하고 같은 UTF-8 표시 경로를 사용한다.
현재 한글 출력 범위는 완성형 한글과 BMP 문자이며 이모지 등 보조 평면 문자는 ?로 대체한다.
자유 입력용 한글 IME 연동과 NPC 대화 시스템 자체는 후속 구현이다.

빌드와 실행
-----------
빌드 및 실행 화면 확인은 사용자 담당으로 남겨 두었다.
이번 작업에서 컴파일, 실행, 성능 측정 또는 화면 캡처는 수행하지 않았다.
코드 연결과 프로젝트 XML에 대한 정적 확인만 수행했다.

1. Visual Studio에서 SimpleGame.sln을 연다.
2. Debug / x64 구성을 선택해 빌드한다.
3. 시작 프로젝트를 SimpleGame으로 지정하고 실행한다.

기존 Win32 및 Release 구성도 유지하며 모든 구성에 OpenGL 링크를 적용했다.
OpenGL 3.3 Core를 지원하는 그래픽 드라이버가 필요하다.
현재 폴더에 포함된 freeglut.dll과 glew32.dll을 해당 플랫폼/구성의
실행 파일 옆에서 사용할 수 있어야 한다.
셰이더는 빌드 시 실행 파일 옆 Shaders 폴더로 복사된다.
실행 디렉터리를 별도로 변경할 필요는 없다.
커스텀 출력 폴더를 사용하면 해당 비트 수의 DLL도 그 폴더에 배치해야 한다.

예상 첫 화면
------------
청록색 바다, 주황색 지붕과 등대가 있는 작은 항구, 야자수와 나무 부두,
항구 옆에 정박한 밝은 돛의 범선을 볼 수 있도록 구성했다.
플레이어는 부두 시작 부분에서 출발한다.
좌측 상단에 제목, 우측 상단에 로컬 지도, 하단에 조작 안내가 나타난다.

조작
----
W / A / S / D : 화면의 위 / 왼쪽 / 아래 / 오른쪽으로 이동
Space        : 누르고 있는 동안 이동 속도 증가
E            : 배 근처에서 승선 / 해안 또는 부두 근처에서 하선
마우스 휠    : 확대 / 축소
+ / -        : 확대 / 축소 (휠 대체)
G            : 청크 경계 표시
H            : HUD 표시 / 숨김
R            : 캐릭터와 배를 출발 항구로 복귀시키는 디버그 기능
Esc          : 종료
P            : 후처리 전체 켜기/끄기 (원본과 비교)
1            : 톤 매핑 켜기/끄기
2            : 비넷 켜기/끄기
3            : 외곽 흐림 켜기/끄기
[ / ]        : 노출 감소/증가 (한 번에 0.1, 범위 0.1~4.0)
0            : 후처리 설정을 기본값으로 복원

승선하려면 부두 끝까지 걸어가 배와 가까워진 뒤 E를 누른다.
부두는 월드 +X 방향으로 뻗어 있어 화면에서는 오른쪽 아래로 보인다.
D와 S를 함께 누르면 그 방향으로 이동한다.
하선은 충분히 가까운 걸을 수 있는 지점을 검색하며, 배는 바다에 남는다.
부두 기둥은 장식이며 부두 전체 직사각형에 충돌을 적용한다.
선박 충돌은 반경 1.2의 원형 근사로, 시각적인 선체 외곽과 완전히 같지 않다.
야자수, 상자, NPC 등 작은 장식에는 개별 충돌이 없다.
섬 중심의 언덕은 오를 수 없는 장애물로 처리한다.

사용자 확인 순서
----------------
1. 첫 화면에서 항구, 캐릭터, 선박과 UI가 표시되는지 확인한다.
2. 창 크기를 바꾸고 휠로 확대/축소해 본다.
3. 해안과 건물을 향해 걸어가 이동 제한이 동작하는지 확인한다.
4. 부두 끝에서 승선하고 항구를 벗어나 항해한다.
5. G로 경계를 켜고 청크 좌표와 로딩된 청크 개수 변화를 확인한다.
6. 다른 섬의 해안에 접근해 하선하고 다시 승선한다.
7. R로 항구에 돌아온 후 다른 지역을 재방문해 동일 지형인지 확인한다.
8. X 버튼 또는 Esc로 종료한다.

후처리 구성과 확인 방법
---------------------
렌더링 순서:
장면 팔레트의 sRGB 색상 → 선형 색상 변환 및 장면 밝기 적용
→ RGBA16F HDR 장면 버퍼 (가능하면 최대 4배 MSAA)
→ 단일 샘플 HDR 텍스처로 해상도 유지 resolve
→ 가로/세로 절반 해상도에서 분리형 Gaussian 블러
→ 원본/블러 영상을 화면 중앙 거리 마스크로 혼합
→ 노출 및 비넷 적용 → 필름형 톤 매핑 → sRGB 화면 출력
→ 한국어 UI와 지도 합성

중앙은 선명하게 유지되고 외곽으로 갈수록 블러와 비넷이 증가한다.
UI, 안내 문구, 지도는 후처리 이후에 그리므로 효과의 영향을 받지 않는다.
현재 비넷/블러 마스크는 화면 비율에 맞춘 타원형이다.
이 효과는 화면 위치 기반 연출이며 깊이 기반 피사계 심도(DOF)가 아니다.

HDR의 의미:
부동소수점 버퍼에서 1.0을 넘는 밝기를 보존하고 최종 단계에서 압축한다.
이번 결과는 일반 SDR 화면용이며 운영체제/모니터의 HDR10 출력을 구현한 것은 아니다.
현재 면별 색상 팔레트에 sceneIntensity=2.0을 적용해 HDR 입력을 만든다.
이는 초기 연출용 밝기 조절이며 물리 기반 태양광/재질/광원 모델은 아직 없다.
톤 매핑은 ACES 계열의 근사 곡선이며 전체 ACES 색 관리 파이프라인은 아니다.
톤 매핑을 끄면 노출 적용 후 SDR 범위를 벗어난 밝기가 잘릴 수 있다.
P로 후처리 전체를 끄면 기존 색상/직접 렌더링 경로로 돌아간다.

조절 기준:
SimpleGame/PostProcessing.h의 PostProcessingSettings에서 기본값을 조절한다.
- exposure: 전체 노출 (기본 1.0)
- sceneIntensity: HDR 장면 밝기 배율 (기본 2.0)
- vignetteStrength: 비넷 강도 (기본 0.24)
- blurRadius: 전체 해상도 기준 블러 샘플 간격 (기본 3픽셀)
- blurStrength: 외곽에서 흐린 영상을 섞는 최대 비율 (기본 0.85)
- blurStart / blurEnd: 흐림 시작/완료 반경 (기본 0.42 / 0.98)
  반경은 중앙 0, 모서리 1 기준이다.
설정은 이번 실행 중에만 유지되며 파일에 저장하지 않는다.

창 크기 변경 시 후처리 버퍼도 다시 생성한다.
블러가 꺼져 있으면 가로/세로 블러 패스를 생략한다.
HDR MSAA 구성이 지원되지 않으면 단일 샘플로 재시도한다.
후처리 셰이더 또는 버퍼 초기화 실패 시 기존 렌더링으로 복귀하고
HUD에 '사용 불가'를 표시하며 콘솔에 원인을 남긴다.

사용자 확인 순서:
1. P를 눌러 원본과 후처리 영상을 비교한다.
2. 2와 3을 각각 전환해 어두워짐과 흐림의 차이를 확인한다.
3. 섬이나 건물이 화면 외곽으로 이동할 때 점점 흐려지는지 확인한다.
4. [와 ]로 노출을 변경하고 흰 돛/모래/어두운 선체의 밝기 변화를 확인한다.
5. 효과 전환 중에도 한글 UI와 지도는 선명하게 유지되는지 확인한다.
6. H로 안내를 숨기고 장면만 비교한다.
7. 창 크기 변경, 최소화/복원 후 화면이 정상적으로 표시되는지 확인한다.
8. 0을 눌러 기본 설정으로 복원한다.

후처리 추가 작업에서는 빌드, 셰이더 실행, 성능 측정 및 화면 검증을 수행하지 않았다.

현재 한계와 다음 단계
--------------------
- 섬과 유적 외형은 생성되지만 고유 아이템, 사연, 퀘스트는 아직 없다.
- NPC는 시각용 모델이다. AI 호출, 대화, 기억, 호감도는 구현하지 않았다.
- 전투, 채집, 무역, 경제, 선원 관리와 배경 시뮬레이션은 아직 없다.
- 청크 생성은 현재 가벼운 동기식 작업이다. 비동기 스트리밍은 후속 단계다.
- 기본 섬은 시드로 재생성하지만 변경분 저장 및 저장/불러오기는 아직 없다.
- 로컬 지도는 현재 로딩된 지형을 보여 준다. 발견 기록/탐험 안개는 아직 없다.
- 월드 생성은 청크당 최대 한 섬의 초기 규칙이다. 문명권/기후 계층은 후속 단계다.
- 메시는 청크에 캐시하지만 CPU 투영과 매 프레임 GPU 업로드를 사용한다.
  대규모 콘텐츠에는 GPU 카메라 행렬, 청크별 VBO, 컬링, 인스턴싱이 필요하다.
- 명암은 면별 색상이며 실시간 조명/그림자, 물 반사/굴절은 없다.
- 청크 좌표는 int64 범위이므로 수학적 무한이 아니다.
- 같은 실행 환경의 시드 기반 재생성을 목표로 한다.
  삼각함수 및 부동소수점 연산의 플랫폼 간 비트 단위 동일성은 보장하지 않는다.
- 자유 항해가 가능하지만 장시간 메모리 사용과 성능은 아직 측정하지 않았다.

주요 파일
---------
SimpleGame/Renderer.h, Renderer.cpp
  색상 메시 생성 도구, 깊이 렌더링, 배치 업로드와 HUD.

SimpleGame/World.h, World.cpp
  청크 좌표, 지형 생성/캐시, 항구 배치와 이동 가능 영역.

SimpleGame/Prototype.h, Prototype.cpp
  캐릭터/선박 모델, 입력 상태, 이동/승하선, 카메라와 화면 구성.

SimpleGame/KoreanText.h
  게임 안내, 상태, 승하선 메시지 등 UTF-8 한국어 문구.

SimpleGame/PostProcessing.h, PostProcessing.cpp
  후처리 설정, HDR/MSAA 프레임버퍼, 해상도 변경과 전체 화면 합성 패스.

SimpleGame/Shaders/PostProcess.vs, PostProcess.fs, Blur.fs
  전체 화면 삼각형, 필름형 톤 매핑/비넷/외곽 혼합 및 분리형 블러.

SimpleGame/SimpleGame.cpp
  창, OpenGL 초기화, 입력/종료 콜백과 타이머 기반 업데이트.

SimpleGame/Shaders/SolidRect.vs, SolidRect.fs
  투영된 정점과 정점 색상을 출력하는 OpenGL 3.3 Core 셰이더.

SimpleGame/SimpleGame.vcxproj, SimpleGame.vcxproj.filters
  신규 파일 등록, OpenGL 링크와 셰이더 배포 설정.

권장 후속 작업
--------------
우선 실행 화면에서 카메라 각도, 전체 색감, 캐릭터 크기, 이동 속도를 조정한다.
그다음 청크별 GPU 메시와 비동기 생성, 발견 기록과 저장을 연결한다.
AI 대화는 NPC 사실/기억/관계 데이터와 권한 검증 규칙부터 준비한 뒤 연결한다.
